# B 版屏幕适配

实现（按用户反馈修正）：读取 Unity `Screen.safeArea`，游戏、UI 和输入共用安全视口。固定竖屏，按原游戏 **固定宽度、可变高度** 适配；取消之前为保留整个 750×1624 手机画布而加入的左右留白。750 是逻辑宽度，1624 是参考高度，不再作为可见高度下限。屏幕越宽，顶部和底部之间的可见区域越短。控件、筹码、进度条等比缩放；顶部/底部随可用高度定位，落币线按原规则调整，提现列表保留滚动。安全区域之外仅显示背景，不能从该区域开始投币。

原版证据（本地完整资源及函数体）：
- `Restoration/05_PrefabModel/HotUpdate/Decoded/3c55dc23-4711-4586-ae5e-7f0601524baa.json`：Canvas 为 `_fitWidth: true`、`_fitHeight: false`，设计尺寸 750×1624。
- `Restoration/02_Gameplay/HotUpdate/Modules/UIUtils.js`：`getScaleRadio` 区分宽度适配/高度适配。
- `GameScene.js`：`adaptPlayAreaForBottomBar` 根据底栏更新地面，并按短屏高度偏差移动预览线/警戒线。
- `GameFakeWDDialog.js`：`adaptLayout` 将顶部/底部固定在当前可见高度内，中间列表随高度变化。
- `AdaptNotchScreen.js`：读取安全区域，调整顶部和底部边距。

换皮后的协议、巴西账号、提现验证面板比矮屏可用高度更高，额外为这三个固定弹窗保存美术边界，并等比缩小到可用范围。这是防裁切补充，不宣称它是原版新增逻辑。主界面和全屏提现页不使用弹窗缩放。

已验证：
- 720×1280、900×1600、1080×1920、1080×2340、1080×2400、1179×2556、1536×2048、1800×2400；两种设计画布及三类安全边界，共 48 组几何断言通过；断言明确检查视口宽度等于安全区域宽度，无额外侧边留白。
- 独立 Unity Play Mode：普通屏、长屏带上下避让、平板，主界面及 11 个菜单页面，共 36 项布局检查通过；检查主要可见按钮越界（滚动区域内元素按其遮罩处理）。
- 同一加载预制体三种屏幕比例的 0%、50%、100% 展示，共 9 项检查通过。
- 之前的安全区域版本曾在 Android 模拟器 900×1600 顶部刘海验证：系统报告可用高度 1528，避让顶部 72 像素。本次按宽适配修改使用独立 Unity 渲染验证，尚未在实体平板重新验收。

边界说明：45 项 Play Mode 检查针对布局，不代表重新测试全部提现业务。1179×2556 等为安全区域模拟，未连接实体 iPhone；灵动岛实际效果须使用 iOS 构建真机验收。Android APK 不能安装到 iPhone。挖孔模拟在用户使用模拟器时发生操作冲突，未算作完成的视觉验收。已恢复模拟器原分辨率并关闭测试 cutout overlay。

视觉结果：1536×2048 主界面和提现页横向铺满安全区域。顶部和底部按钮保持原比例；提现页同时可见的档位减少，需要滚动查看其余档位。加载插画保持宽度等比覆盖，较短屏幕会裁去插画下部；进度条和文字独立锚定并保留。没有声称所有品牌、所有实体机型均已验收。

提现分割线：禁用顶部局部天空切片和底栏单独的高亮横边图，改为显示连续页面背景。列表遮罩增加 12 像素柔化，保留提现按钮原尺寸、图片和交互。对应 `CashSeamRepair` 作者工具；无图片重绘或玩法修改。

复核工具：`DeviceSafeAreaChecks.Run`、`DeviceLayoutReview.Run`（仅在独立验证副本运行）。截图与日志保存在忽略的 `Restoration/Builds/Android/DeviceLayoutReview`，不提交设备材料。

依据：[Unity Screen.safeArea](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Screen-safeArea.html)。
