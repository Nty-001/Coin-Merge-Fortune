# B 版屏幕适配

实现：读取 Unity `Screen.safeArea`，游戏、UI 和输入共用安全视口。固定竖屏；内容等比缩放以保证至少 750×1624 的设计区域完整显示；短屏、平板两侧补连续天空背景。加载页按自己的 750×1332.625 设计比例适配。控件、筹码和进度条不会被非等比拉伸。输入不再从视口外开始投币。

已验证：
- 720×1280、900×1600、1080×1920、1080×2340、1080×2400、1179×2556、1536×2048、1800×2400；两种设计画布及三类安全边界，共 48 组几何断言通过。
- 独立 Unity Play Mode：普通屏、长屏带上下避让、平板，主界面及 11 个菜单页面，共 36 项布局检查通过；检查主要可见按钮越界（滚动区域内元素按其遮罩处理）。
- 同一加载预制体三种屏幕比例的 0%、50%、100% 展示，共 9 项检查通过。
- Android 模拟器 900×1600 顶部刘海：系统报告可用高度 1528，游戏内容避让顶部 72 像素；APK 编译与安装成功。

边界说明：45 项 Play Mode 检查针对布局，不代表重新测试全部提现业务。1179×2556 等为安全区域模拟，未连接实体 iPhone；灵动岛实际效果须使用 iOS 构建真机验收。Android APK 不能安装到 iPhone。挖孔模拟在用户使用模拟器时发生操作冲突，未算作完成的视觉验收。已恢复模拟器原分辨率并关闭测试 cutout overlay。

代价：较宽屏幕上内容会缩小并出现两侧背景留白，这是为了保留完整竖屏内容及按钮比例。没有声称所有品牌、所有实体机型均已验收。

复核工具：`DeviceSafeAreaChecks.Run`、`DeviceLayoutReview.Run`（仅在独立验证副本运行）。截图与日志保存在忽略的 `Restoration/Builds/Android/DeviceLayoutReview`，不提交设备材料。

依据：[Unity Screen.safeArea](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Screen-safeArea.html)。
